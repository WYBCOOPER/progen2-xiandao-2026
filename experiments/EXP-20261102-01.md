## 改动内容

只把每层 4 个大矩阵（占全部参数 99.9%）的**权重**换成 fp16，其余全部保持 fp32：

| 位置 | 精度 |
|---|---|
| `qkv_proj` / `out_proj` / `fc_in` / `fc_out` 的矩阵乘 | fp16 权重 + fp16 输入，输出立即 `.float()` |
| 偏置加法 | fp32 |
| 激活值、LayerNorm、attention 分数（QK^T）、softmax、KV Cache、lm_head、logits、argmax | fp32 |

实现方式：`solution.py` 中新增 `_HalfWeightLinear`（`F.linear(x.to(fp16), w_fp16).float() + bias(fp32)`），
`_install_half_weights()` 在 `model.eval().to(device)` 之后、`torch.compile` 之前替换 27 层的 4 个 Linear。

回退开关（`solution.py` 顶部常量）：
- `WEIGHT_DTYPE = "fp16"` → 可改 `"bf16"`；
- `HALF_WEIGHT_SCOPE = "all"` → 可改 `"mlp"`（只换 fc_in/fc_out，约 80% 参数）。

## 观察、异常或失败原因

### v4 首轮（2026-11-02 22:47，结果目录 v4-5b30ef2-20261102-Uzx055）

- 运行信息：`权重半精度已开启: torch.float16, 替换 108 个 Linear`、`torch.compile 已开启`、`Loaded in 20.082s`；
- 警告：inductor 提示 "TensorFloat32 tensor cores ... available but not enabled"；编译期多条 `symbolic_shapes.py:4449 xindex is not in var_ranges`；
- 结果：2.3887 / 2.9448 / 5.8598 / 0.7525s，一致率 **0.39% / 16.02% / 1.37% / 7.42%**（same 1/256、328/2048、28/2048、19/256）；
- 形态：load1 只对 1/256，第一个字母即错 → 不是逐步漂移，而是半精度路径本身算错；同时耗时比 main 慢约 8%，既没加速又破坏数值。

### T1（2026-11-03，关闭 fp16 低精度累加，compile 保持开启；结果目录 pr24-1bda90f-t1-20261103-2GBzzu）

- 运行信息：`权重半精度已开启: torch.float16, 替换 108 个 Linear`、`torch.compile 已开启`、`Loaded in 9.871s`；
- 四项耗时 2.4295 / 3.0256 / 6.0288 / 0.7740s，**一致率 0.39% / 16.02% / 1.37% / 7.42%**；
- **关键观察：四项 same/total 与 v4 首轮完全相同（1/256、328/2048、28/2048、19/256）**。
  若误差确实来自 fp16 累加，关闭 reduced-precision reduction 后误差应显著变化（即使不恢复 100%，数字也不会分毫不差）——
  因此结论：**该开关在 DCU/hipBLAS 上对这条路径没有生效，或者误差不来自累加**。
- `T1_CHECK=FAIL`（脚本明确提示 accuracy mismatch，保留证据、不得作为采用方案）。

### 下一步 T2 + GEMM 体检（2026-11-03）

本分支同时提供：
1. `submission/solution.py` 已置 `COMPILE_MODEL = False`（T2）：判断误差是否来自 compile/融合；
2. `dev/check_fp16_gemm.py`：不跑模型，10 秒直接测 DCU 上 fp16 GEMM 的实际误差，区分"权重舍入"与"GEMM 实现/累加"两类问题。

判读标准（体检脚本）：
- 若 `1) fp16 matmul (default)` 的 `max_abs/ref_std` 在 **1e-3 量级** → fp16 GEMM 本身可用，问题在 compile 或其他路径；
- 若达到 **1e-2 ~ 1e-1**，且 `2) reduced=False` 明显变小 → 累加开关有效但 v4 未生效（需确认执行的是新代码）；
- 若两组都很大、而 `3) fp32 compute + fp16 weights` 很小 → **DCU 上 fp16 GEMM 实现不可信**，本方案直接放弃。
