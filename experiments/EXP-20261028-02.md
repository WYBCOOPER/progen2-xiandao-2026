## 运行方法

先备份接口骨架、从 baseline/solution.py 复制实验入口，再改精度及文字标记。在官方题包根目录执行：

```bash
set -o pipefail
bash run_public_test.sh submission 2>&1 | tee results/fp16_trial.log
```

默认 JSON 写到 results/submission_public.json；每负载先预热一次、正式计时一次，遵循官方脚本。实验后将代码、JSON 和日志归档到 results/fp16_trial/，然后把工作入口恢复为原始 FP32。

## 结论与限制

四项输出格式通过；四项本轮耗时均长于 FP32。第二项一致率为 69.140625%，第三项为 69.677734375%，均低于该负载的 80% 性能准入门槛。总体等权一致率为 84.70458984%。本轮未观察到加速，不采用这份直接 FP16 方案；不能从单轮断言所有 FP16 方案一定更慢。

模型加载 5.825 秒不计入成绩，也不能与基准加载时间直接比较后宣称推理加速。低精度数值误差可能改变贪心选择并使后续序列分岔，但未定位首次分岔或排查算子耗时，原因仍待分析。未采集显存或性能剖析数据。

当前 submission/solution.py 已恢复 FP32，与原始基准字节一致；本实验的 JSON 仍描述恢复前的 FP16 快照，不能把它与恢复后的代码混成最终提交。正式作品还需后续开发、独立复核与最终一轮测试。
