# FP32 输入投影融合（独立候选）

上传 ZIP 到现有 progen2_contest 目录，在该目录逐条执行：
```bash
unzip -n fp32-input-fuse-v4-upload.zip
bash candidates/fp32_input_fuse_v4/run_test.sh
```

基于已通过 DCU 测试的 fp32_step_gemm_v23，把每层读取同一输入的 QKV 投影和 MLP 第一层合成一次 FP32 矩阵乘，再拆开输出。保留静态 KV、RoPE 表、单步编译、矩阵乘调优和贪心生成规则。这里的 v4 是 FP32 输入融合候选，与 PR24 半精度版本不同。

融合在 Solution 初始化时完成，不使用请求输入，也不提前计算请求相关 KV。原始权重文件、官方基准、测试器和既有 submission 不修改。参数重排保持 state_dict 名称和值；融合缓冲区不存入权重，原参数共享其存储，避免长期保留一份重复权重。GEMM 形状改变可能造成浮点舍入差异，不能预先保证完整生成一致。

本地验证：官方真实权重和 27 层模型的四组缩短生成共 152 个输出，与父版和参考前缀一致，并检查交错请求的缓存独立性。另通过 CPU/NVIDIA 实际 block 的数值、KV、偏置及 fullgraph 捕获检查。使用加载兼容层，未运行完整官方测试、Inductor 或 DCU，不作为加速证据。

运行脚本自动校验指纹，新建 results/fp32-input-fuse-v4-日期-随机码，保存源码、版本、四项成绩、日志和编译检查，正常结束或运行失败均尝试打包。结束时按 RESULT_ARCHIVE 路径下载结果包。

接受条件：四项生成均与官方参考 100% 一致，四次正式计时调用的 Dynamo 编译事件均为 0，日志确认 27 层融合已开启。预热中的编译可以发生。收益须与同环境下父版对照，当前未在 DCU 测试，不预填加速结论。
