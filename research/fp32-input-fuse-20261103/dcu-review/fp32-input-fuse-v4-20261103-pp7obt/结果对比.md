# FP32 输入投影融合 v4：DCU 结果

结论：四项正确性与编译事件检查通过，但本轮没有证明整体加速。保留父版 fp32_step_gemm_v23。

| 负载 | 父版历史耗时 / 秒 | 本轮融合版 / 秒 | 耗时变化 |
|---|---:|---:|---:|
| 1 | 1.7064 | 1.7563 | +2.93% |
| 2 | 1.8221 | 1.8743 | +2.87% |
| 3 | 3.6051 | 3.6767 | +1.99% |
| 4 | 0.5469 | 0.5344 | -2.28% |
| 合计 | 7.6804 | 7.8417 | +2.10% |

正值表示更慢。合计仅用于描述这四项耗时，不代表赛事评分公式。

核验：输出 4608/4608 一致；八次 generate 的编译事件为 [3, 0, 3, 0, 0, 0, 0, 0]，四次正式计时均为 0；27 层融合已开启；退出码 0。包内九份源码及辅助文件与发出的测试 ZIP 逐字节一致，八份指纹均通过。

本轮环境：Python 3.10.16、PyTorch 2.4.1、HIP 6.1.25065、Triton 3.0.0+das.opt4.dtk2504、设备 BW。对照来自已核验源码的 fp32-step-gemm-v23-20261103-mP5cp4，软件版本和设备型号相同，但不是本轮紧邻测试，不能确认同一物理卡或系统负载相同。因此不能据此认定稳定退化，也不能记录为优化收益。

【关联前面】融合减少了投影调用次数，但矩阵形状、输出存储布局和编译器选择的实现也会改变；“调用更少”不直接等于“端到端更快”。日志显示新投影形状包含 mm(8x1536,1536x10752)，只能确认新路径被使用，不能单独解释耗时差异。

下一步：若继续评估融合，先在同一容器补跑父版作为当前对照；边际差异需要交替复测两版再判断。若暂不复测，状态保持“收益未证实”，继续使用父版。原结果包及 evidence 中的源码、日志、成绩保留原样；manifest 内的 DCU_tested=false 是发包前快照，不回写修改。
