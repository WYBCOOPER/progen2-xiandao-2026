## 改动内容

只把每层 4 个大矩阵（占全部参数 99.9%）的**权重**换成 fp16，其余全部保持 fp32：

| 位置 | 精度 |
|---|---|
| `qkv_proj` / `out_proj` / `fc_in` / `fc_out` 的矩阵乘 | fp16 权重 + fp16 输入，输出立即 `.float()` |
| 偏置加法 | fp32 |
| 激活值、LayerNorm、attention 分数（QK^T）、softmax、KV Cache、lm_head、logits、argmax | fp32 |

实现方式：`solution.py` 中新增 `_HalfWeightLinear`（`F.linear(x.to(fp16), w_fp16).float() + bias(fp32)`），
`_install_half_weights()` 在 `model.eval().to(device)` 之后、`torch.compile` 之前替换 27 层的 4 个 Linear。

回退开关（`solution.py` 顶部常量）：
- `WEIGHT_DTYPE = "fp16"` → 可改 `"bf16"`；
- `HALF_WEIGHT_SCOPE = "all"` → 可改 `"mlp"`（只换 fc_in/fc_out，约 80% 参数）。

## 观察、异常或失败原因

### DCU 首轮（2026-11-02 22:47 左右，v4-5b30ef2-20261102-Uzx055）

- 启动信息：`权重半精度已开启: torch.float16, 替换 108 个 Linear（scope=all）`、`torch.compile 已开启`、`Loaded in 20.082s`；
- 警告：inductor 提示 "TensorFloat32 tensor cores for float32 matrix multiplication available but not enabled"；编译期出现多条 `symbolic_shapes.py:4449 xindex is not in var_ranges` 警告；
- 结果：四项耗时 2.3887 / 2.9448 / 5.8598 / 0.7525s，**一致率 0.39% / 16.02% / 1.37% / 7.42%**；
- 关键形态：load1 只对 1/256，**第一个字母就错**，不是"生成到一半漂移"，说明半精度矩阵乘路径本身算错（或与其后的编译/attention 路径不兼容），而不是累积舍入误差；
- 同时耗时比 main 慢约 8%，说明这次尝试**既没加速、又破坏了数值**。

推测原因（按可能性排序）：
1. **fp16 低精度累加**：PyTorch 默认 `allow_fp16_reduced_precision_reduction=True`，hipBLAS 可能采用 fp16 累加，误差足以让 argmax 全错；
2. **torch.compile 与自定义半精度模块交互**：编译期 `xindex` 动态形状警告、以及 fp32/fp16 混合路径的图融合可能改变了数值路径；
3. 半精度范围问题（如 qkv 输出/中间量溢出），但第一个 token 即错更像累加精度或编译问题。

## 诊断计划（本分支已加入开关，单变量逐个排除）

`submission/solution.py` 新增两个开关：
- `ALLOW_FP16_REDUCED_PRECISION = False`（默认已加，用于排除原因 1）；
- `COMPILE_MODEL = True`（改 False 可排除原因 2）。

| 测试 | 变量 | 期望 |
|---|---|---|
| T1 | 当前版本（关闭 fp16 低精度累加，compile 开） | 一致率恢复 100% → 根因是累加精度 |
| T2 | T1 失败 → `COMPILE_MODEL=False` | 若恢复 → 根因是 compile 交互 |
| T3 | 仍失败 → `HALF_WEIGHT_SCOPE="mlp"` | 排除 attention qkv/out 半精度 |
| T4 | 仍失败 → `WEIGHT_DTYPE="bf16"` | 排除 fp16 范围问题 |
