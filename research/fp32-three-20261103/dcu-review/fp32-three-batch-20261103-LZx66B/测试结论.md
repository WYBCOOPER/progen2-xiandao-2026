结论：继续保留 v23。本批三项均跑完、公开输出均为 4608/4608 一致，四次正式计时的 Dynamo 编译事件均为 0，但没有新增可确认的整体提速。连同此前输入融合，共完成四项改动测试。

核验：三份退出码均为 0；每项九份源码和辅助文件与发出的 ZIP 逐字节一致，每项八份指纹均通过，父版源码与已核验 v23 一致。成绩 JSON 与完整日志吻合。三项环境记录一致：PyTorch 2.4.1、HIP 6.1.25065、Triton 3.0.0+das.opt4.dtk2504、设备 BW；父版 Triton 记录口径为模块 __version__，不直接将其与发行版元数据字符串差异判为环境变化。

K 布局注意事项：预热调优期间出现 PassManager::run failed 和 operand #0 does not dominate this use。日志随后明确写 Ignoring this choice，继续选择其他候选并跑完；这些是被忽略的调优候选编译失败，不是整项测试中止。报错证据按原样保存；不能因最后 PASS 就省略，也不能据此声称完全退回 eager。正式计时监测事件仍为 0。

【关联前面】减少 Python 调用、改变缓存布局、换用统一注意力接口，都只是优化假设。最终实现可能改变内核选择、存储访问或中间结果，因此必须用端到端耗时验证。本轮不能仅凭耗时定位两步生成或 SDPA 较慢的根因；v6 的约 0.40% 差异不足以单轮确认收益。

下一步：不合并这三项、不再组合 v5/v6/v7。若继续筛选，优先只复测 v23 与 v6，交替运行多轮看中位数与波动；v5、v7 暂停。需要继续开发时，先对 v23 采集算子级或时间线诊断，再选择新改动，避免按改动数量判断进展。
